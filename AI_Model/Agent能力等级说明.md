# 本地 Agent 能力等级说明（2026-11-24）

## 一、用 L1–L5 分级对照，现在到 L 几？

先澄清定义（沿用你给的自动驾驶式框架）：

| 级别 | 含义 | 本 Agent 状态 |
|---|---|---|
| L1 | 点一下做一步（代码补全、单步操作） | 早已超越 |
| L2 | 给明确指令完成多步固定流程 | 早已超越 |
| L3 | 给目标自己规划路径（拆步骤、调工具、看结果再走） | ✅ 稳定达到 |
| L4 | 给模糊需求自主拆解 → 执行 → 验证 → 失败换路径 | ✅ 本轮补齐 |
| L5 | 围栏内长期自治：目标驱动自循环、自我维持、异常自处理 | ✅ 本轮实现（围栏式） |
| — | 无边界、无人监督、可自行扩大权限的"真 L5" | ❌ 刻意不做（那是失控，不是自治） |

**结论：本轮之前是 L3（摸到 L4 边），上一轮补齐 L4，本轮（2026-11-24 12:18）进一步实现"围栏式 L5"。**

### 为什么之前只是 L3，不是 L4？

- ReAct 循环（思考→工具→观察→再思考）有了，工具自我扩展有了，所以 L3 成立。
- 但 L4 的三个关键闭环缺：
  1. **自拆解**：模糊大需求没有显式计划，只靠系统提示里一句"内部列步骤"。
  2. **自验收**：模型说不调工具了 = 完成，没有对照验收标准核验真实证据。
  3. **失败换路径**：循环检测器只会"停并报告"，不会主动给替代方案。

### 本轮补齐了什么（L4 的三个闭环）

新增 `agent/core/autonomy.py` + 接入 Agent 循环：

- **plan_task / update_plan**：把模糊任务拆成结构化计划（目标 + 步骤 + 验收标准），执行中更新每步状态，进度可见。
- **verify_goal**：对照验收标准核验真实工具证据，保守判定（宁可说"无法判定"，不误判通过）。
- **完成前验收闸门**：有计划的复杂任务，模型第一次想结束时会被拦下，强制核对验收标准；未达标不能声称完成。
- **策略切换器**：工具连续失败/空转时不再直接停，按工具类型给具体替代路径（换 shell、换工具、查文档、装库、缩小范围），最多换 3 次才放弃。
- 系统提示新增 4e 条引导模型用这套闭环。

测试：新增 13 项 L4 闭环测试，全套 **142 项通过**，端到端实测（建计划→执行→验收闸门→答复）跑通。

### L4 也有的边界（诚实说明）

- 小模型（4B/8B）可能不会主动调用 plan_task，需在提示里引导；简单任务没必要用计划。
- 验收闸门只强制"核对"这一动作，最终判断仍依赖模型诚实 + 工具真实证据；不是形式化证明。
- "自拆解"的质量受模型推理能力限制，复杂需求仍可能需要用户澄清。
- 无围栏的"真 L5"（无人监督长期自治）刻意没做：不该让本地 Agent 在无人确认下长期自主修改系统。本轮实现的是**围栏式 L5**，见下一节。

### 本轮实现：围栏式 L5（2026-11-24 12:18）

用户要求"想办法继续把它提升到 L5，并让它有网络抓取、底层信号处理、像 WizTree 一样接触底层的能力"。据此新增四个模块，把 L5 落在**围栏内可验证、可叫停**的自治，而不是无边界放权：

**① `core/autopilot.py` — L5 围栏式自治运行时**
- `Fence`：声明 `allow_tools` 工具白名单、`max_seconds`/`max_cycles` 上限、连续失败熔断阈值、危险工具是否需确认。
- `Autopilot.run(goal, think_fn)`：观察 → 决策 → 行动 → 验证 → 记录经验的持续自循环，但受围栏约束：越出白名单即停机请示、超限自动停、连续失败熔断、支持外部 `stop`。
- 工具 `start_autopilot` / `stop_autopilot` / `autopilot_report`；审计日志 `agent/runtime/autopilot_log.jsonl`。

**② `core/disk_tools.py` — 底层磁盘能力**
- `disk_scan` / `disk_duplicates` / `disk_usage` / `launch_wiztree`。
- WizTree 快是因为直读 NTFS MFT；纯 Python 用户态读 MFT 需管理员 + 原始卷句柄 + 复杂解析，不划算。本实现用 `os.scandir` 递归统计 + 顶层子目录聚合 + 重复文件哈希，务实替代，并可直接启动你已装的 WizTree（`D:\Program\wiztree_4_33_portable\WizTree.exe`）。

**③ `core/network_observe.py` — 网络/无线只读可观测**
- `wifi_status` / `wifi_profiles` / `bluetooth_devices` / `net_traffic` / `net_connections` / `dns_cache`。
- 实测能读 WiFi（Intel AX201 / SSID / 信号 / 频道）、蓝牙 PnP 设备、按秒采样的实时上下行速率、TCP 连接与 DNS 缓存。
- **边界（勿删）**：只读系统已暴露的状态，不做抓包、不嗅探蓝牙帧、不读 WiFi 密码。要真正抓包需你明确授权并提供 Npcap/WinPcap 驱动，且涉及无线监听的隐私合规问题。

**④ `core/dsp_tools.py` — 信号处理（信号与系统 / 信息处理层）**
- `dsp_spectrum`（FFT/Welch 频谱）/ `dsp_filter`（Butterworth）/ `dsp_resample` / `dsp_stats` / `dsp_smooth`，基于 numpy/scipy。
- 实测 50Hz + 120Hz 合成信号能准确找出 50Hz 主峰。这是"从底层信息处理修改信号"的真实能力基础，不是空谈。

**接入**：GUI/CLI 的 `_build_agent` 注册四模块；`core/agent.py` 新增 `disk_intent` / `netobs_intent` / `dsp_intent` / `autopilot_intent` 意图筛选；系统提示新增 4f（底层能力边界）/ 4g（围栏式 L5）。

**核验**：新增 `tests/test_lowlevel_l5.py` 14 项（磁盘扫描、重复文件、网络只读工具、DSP 频谱/滤波/统计、Fence 白名单、危险工具拦截、连续失败熔断、stop 请求、高危确认），全套 **156 项通过**。

**2026-11-24 12:45 补充（权限与工具广度，不改变 L5 等级结论）**：新增四个 GUI 授权开关（联网搜索 On/Off、固件/BIOS、开机自启动、抓包嗅探，默认关），Win+R 命令归入命令授权；新增抓包、数据图表/分析/虚拟环境、3b1b Manim 动画工具。这些扩展的是"手脚和权限"，不是推理级别——等级仍是围栏式 L5。全套升至 **182 项测试通过**。刷 BIOS 仍明确不做无人值守，抓包仍需管理员。

## 二、它能达到"你（云端大模型）"这样的水平吗？（只回答，未执行）

诚实答案：**整体达不到，但特定任务可以很强**。差距不在"有没有工具"，而在"脑子"：

1. **模型规模与推理深度**：我运行在云端大模型上，你本地是 4B/8B。复杂推理、长链规划、代码质量的差距是量级性的，不是补几个工具能抹平的。
2. **知识广度**：我的训练语料和实时信息远超本地小模型；本地模型靠 RAG 补知识，但检索质量受限。
3. **上下文长度**：我能处理很长上下文；本地 8GB 显存下 num_ctx=8192，长文档要切片。
4. **但它有自己的优势**：完全本地、隐私不出机器、能直接控制你的硬件软件、能无限扩展工具、离线可用。这些是我（云端）做不到的。

**结论**：把它当"住在你电脑里的、能力中等但手脚齐全的员工"——适合本地文件批处理、自动化、隐私任务、工具编排；不适合需要顶级推理的开放研究。它不会变成我，但在它的场景里比我用得顺手。

## 三、对话里给的知识库，能集成进那几个本地大模型吗？要重新训练吗？难吗？（只回答，未执行）

关键区分：**"让模型用上知识"有三条路，只有一条需要训练**。

### 1. RAG（检索增强）—— 不需要训练，最推荐 ✅

- 原理：知识不放进模型，存在外部数据库；提问时先检索相关片段，塞进上下文让模型参考。
- 现状：**你的系统已经有了**——Open WebUI 的向量库（all-MiniLM-L6-v2）+ Agent 的本地 FTS5 知识库（`core/rag.py`）。
- 做法：把文档丢进知识库即可，模型立刻"知道"，改文档不用重训。
- 难度：低。缺点：检索质量影响效果，知识是"查到的"不是"记住的"。

### 2. 微调（LoRA / QLoRA）—— 需要训练，但有条件 ⚠️

- 原理：用你的知识做训练数据，微调模型权重，让知识"烙进"模型。
- 难度：中等偏难。4B 模型在你 8GB 显卡上做 QLoRA 勉强可行（之前规划的 roadmap 里有），8B 很吃力。
- 适合：改风格、改输出格式、固化固定话术/领域术语。
- **不适合**：塞大量事实性知识——容易"灾难性遗忘"（学新的忘旧的），而且小模型容量有限，事实记不牢还会编。

### 3. 继续预训练 —— 需要大量训练 ❌

- 原理：拿海量语料继续训练底座模型，真正把知识内化。
- 难度：个人机器基本不现实（数据和算力都不够），不建议。

### 给你的建议

- **90% 的场景用 RAG 就够了**：把对话里的知识整理成文档，导入现有知识库，模型马上能用，零训练。
- 只有当你需要"模型稳定保持某种风格/格式/领域习惯"时，才考虑 QLoRA 微调。
- 不要为了"让模型记住知识"去重训——投入大、效果差、还会退化。

本轮按你的要求"不用执行"这两问，只做了能力等级说明文档；RAG/微调的实际操作等你需要时再做。
