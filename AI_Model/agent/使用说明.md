# 本地 Agent 使用说明

一个跑在本机、用本地 Ollama 模型驱动的 AI Agent，类似 Claude Code / Codex。

**模型和对话历史在本机运行，不花云端积分。**配置浏览器、邮箱或 GitHub MCP 后，相应 MCP 工具会访问外部服务。

## 启动（推荐：桌面图标，最简单）

**桌面已经有一个「本地AI Agent」图标，双击就打开完整窗口。**

- 不用开 BAT、不用开浏览器
- Ollama 没运行会自动拉起来
- 点击左上角 `☰` 打开侧栏；模型和工作空间在“设置”页，底部输入框输入任务，`Enter` 发送，`Shift+Enter` 换行（`Ctrl+Enter` 也可发送）
- 输入区“＋ 文件 / 图片”可打开附件选择器；支持的文件类型会随所选模型显示
- 可从资源管理器复制文件后在输入框按 `Ctrl+V`，也可把文件拖到对话区/输入框；支持的文件会显示在输入区
- 也可附加常见代码或文本文件（单个不超过 200 KB）；图片单个不超过 15 MB
- 点击顶栏左侧 `☰` 展开/收起功能侧栏：会话、知识库、终端、Git、技能、MCP、设置和执行日志都在侧栏内
- Ollama 回复会逐段流式显示，不必等整轮生成结束
- 推理模型尚未生成答案时，状态栏会显示推理活动进度；内部推理原文不会混进最终回答
- 打开侧栏后可拖动聊天与侧栏之间的分隔条；输入框随聊天栏宽度缩放，窗口改变大小时会保持分栏比例。常用按钮有淡色悬停反馈
- 模型能力会显示在状态栏：`qwen2.5vl:7b` 只支持看图聊天；`qwen3.5:4b` 支持看图和 Agent 工具；代码任务可选 `qwen2.5-coder:7b` 或 `deepseek-r1:8b`
- 想同时看图和操作文件时，在侧栏“设置”选择 `qwen3.5:4b`；纯文本模型无法识别图片
- 如果选了不带工具的模型，却提出打开应用、运行命令、操作文件、查设备或生图等任务，GUI 会在检测到本地可用模型后自动切换到支持工具的模型；没有可用工具模型时会明确告知，不会伪称执行成功
- Agent 回复中的 Markdown 标题、粗体、行内代码和 fenced 代码块会在对话中即时渲染。流式输出期间代码块也会逐步显示
- 对话文字可拖选后按 `Ctrl+C`，也可右键复制选中内容或整段对话；`Ctrl+A` 选中聊天记录
- 生成图片双击可放大，鼠标滚轮或 `+` / `−` 调整缩放；右键可复制图片、复制路径或打开图片文件夹

如果桌面图标丢了，双击 `scripts\创建桌面快捷方式.bat` 重新生成。

### 备选：命令行版本

如果更喜欢终端，双击 `scripts\5-启动本地Agent.bat`，用法见下面的交互命令部分。

### 直接输入需求

比如"帮我看看这个目录里有什么文件"，Agent 会自己读文件、跑命令、改代码，直到完成。

## 它跟普通聊天有什么区别

普通聊天只能"说"，Agent 能"做"。它会：

1. 理解你的需求
2. 自己决定调哪个工具（读文件、搜索、执行命令）
3. 看工具返回的结果
4. 继续下一步，直到任务完成

全程自主循环，你只管下指令。

## 侧栏功能

历史记录从此版本开始保存到本机 SQLite；此前未持久化的旧聊天不会自动补回。

- **会话**：历史对话保存在本机 `agent/data/history.sqlite3`，可双击或选中后打开，也可确认后删除。对话标题取自首条提问。
- **知识**：在当前工作空间添加和管理本地 RAG 文件。
- **终端**：选择 PowerShell 或 CMD 输入命令；每条命令运行前都会确认，最多 120 秒。
- **权限设置**：可勾选“允许访问工作空间以外的本机文件”；启用时会二次确认，外部删除/写入与命令仍逐次确认。管理员身份需点“以管理员身份重启”，并在 Windows UAC 窗口中确认；UAC 未确认不会提权。管理员模式可通过“切换到普通用户模式”返回。
- **文生图**：使用支持工具调用的模型提出“生成一张……图片”，Agent 会确认后调用本机 ComfyUI 的 Z-Image-Turbo，必要时在后台启动 ComfyUI。为让出显存，会先卸载驻留的 Ollama 模型（下一轮会自动重新加载）。生成结果嵌入对话并保存于 `AI_Model/ComfyUI/output/`。尺寸上限 1024，步数上限 12；启动及生成受内存/显存预检保护。
- **Git**：读取当前工作空间的分支、文件状态、远程地址和最近提交。提交、拉取、推送等写操作可在终端执行，并需确认。
- **技能**：导入包含 `SKILL.md` 的文件夹；新技能在下一条任务加载。技能说明会进入模型上下文，请只导入可信内容。
- **MCP**：添加本地 MCP Server 的启动命令、参数和环境变量。支持的浏览器、邮箱、GitHub 能力取决于你安装和授权的具体 MCP Server。服务会在 Agent 创建时启动；每次 MCP 工具调用都需确认。
- **Windows 桌面工具**：`system_info`/`workspace_info` 查询真实系统和工作空间；`query_devices` 通过 Windows 即插即用设备清单查询设备。打开软件时使用通用 `open_application`：按开始菜单 `.lnk` 显示名、Windows App Paths 注册表、PATH 的顺序发现（PATH 支持名称片段/缩写），不依赖 VS Code 专用启动路径。Windows 接收启动请求后最多轮询 12 秒查找可见顶层窗口；只有看到窗口才报告成功，并提供窗口标题和可用 PID。此检查按需运行，不是常驻后台监听器。找不到软件时可提供 `.exe` 或 `.lnk` 完整路径。`open_vscode` 只是兼容旧调用名。
- **创建和打开文件**：明确要求创建文件时会调用写入工具，支持 Python、BAT/CMD、Markdown、JavaScript/TypeScript、C/C++、Java、TXT、JSON、HTML、CSS、PowerShell 等常见源码和文本类型；写入后会验证文件存在且内容一致，覆盖旧文件前会确认。可要求“打开 `文件名.md`”或给带空格的绝对路径；代码/脚本默认用 Windows `edit` 动作打开编辑器，避免意外执行 BAT/PS1 等文件，其他文档使用系统默认打开动作。文件操作仍受工作空间及“完整本地访问”设置约束。
- **浏览器**：已配置 Microsoft Playwright MCP 和 Edge 集成。它启动单独的受控 Edge 实例及 `agent/data/playwright-profile` 用户资料目录，不是接管你平时已打开的 Edge；登录状态也彼此隔离。Agent 可导航、读取页面快照，并按任务调用点击/填写等操作。它不等同于联网搜索；天气/新闻等问题优先走 `web_search`。网页上的写入/提交操作仍需确认。

Playwright MCP 使用隐藏的后台进程，不应再弹出 Node 控制台窗口。Agent 会按当前请求筛选浏览器工具；一般聊天和本机文件任务不会把全部浏览器工具定义塞进模型上下文。

### 四个模型的能力差别

GUI 通过 Ollama 获取模型能力，并对当前四个模型提供以下已知默认映射：`qwen2.5vl:7b` 支持视觉、不提供工具调用；`qwen2.5-coder:7b` 支持工具；`deepseek-r1:8b` 支持工具和思考；`qwen3.5:4b` 支持工具、视觉和思考。Ollama Provider 对四者都使用流式 API；是否能自主调本地工具取决于模型本身是否支持工具调用，GUI 对常见任务会切换到支持工具的模型。联网搜索和读取本机时间由 Agent 外层直接提供，因此不依赖模型的原生工具调用，但最终总结质量仍受所选模型能力影响。

实时搜索通过 Bing RSS 获取搜索引擎的摘要元数据，会从带上下文的提问中提取实际搜索短句，并过滤不含主题词的无关结果；不等于浏览器已打开并核读网页全文。结果仍可能排序不佳、过时或摘要不准；涉及数学突破、新闻等重要说法，应优先核对论文、官方声明和独立验证来源，并明确发布日期。无相关结果/搜索失败时 Agent 会报告无法核实，而不是假称搜索成功。本机日期询问由 `current_datetime` 直接读取，不交给模型猜测。

询问“我在哪”“电脑公网 IP”会直接调用 `network_location` 查询出口 IP 和 IP 库中的粗略归属。该请求会向 ip.guide 发起网络请求，第三方会看到请求来源 IP；结果不是 GPS，VPN/代理可能显示出口服务器位置。Agent 不得把工作空间路径当成地理位置。

PDF/DOCX 可在“知识”中加入 RAG，也可要求 Agent“把 `xxx.pdf` 转成 Markdown”，输出为同目录下 `xxx.extracted.md`；已有输出文件会要求确认覆盖。扫描件需要额外 OCR，当前转换不会保证保留复杂表格或版式。通用 ZIP/7z 压缩解压还没有内置为 Agent 工具。

MCP 环境变量可用 `${VARIABLE_NAME}` 引用 Windows 环境变量，避免把令牌明文写入 `mcp_servers.json`。本 GUI 不会替你登录邮箱或浏览器，也不内置某个平台的 OAuth 流程。

### 邮箱 MCP（Gmail / QQ 邮箱）

仓库提供本地 `tools/email_mcp_server.py`，使用 Python 标准库的 IMAP over SSL / SMTP over SSL；目前支持查看最近未读邮件和发送纯文本邮件。每次 MCP 调用（包括发送）都会由 Agent GUI 弹出确认。附件、删除邮件、移动邮件和搜索全邮箱暂不支持。

在 GUI 的 `☰ → MCP` 页点击“添加我的 QQ / 163 邮箱”，会为 `897438850@qq.com` 与 `15191169780@163.com` 写入两个本地 MCP 服务入口。此动作只写地址/服务器名，不会登录或收发邮件。然后点击“保存应用授权码”，分别从邮箱服务生成并输入 IMAP/SMTP 授权码；输入框会掩码显示，凭据写入 Windows 凭据保管库。

明确提出读取 QQ/163 收件箱时，Agent 会直接路由到对应 MCP 读取工具，不依赖模型自行想起工具；GUI 仍会要求确认。若没有加载该服务，会说明具体的 MCP 名称，不再编造 `read_email` 命令或说账号没有提供。

如果曾遇到 `AttributeError: type object 'IMAP4' has no attribute '_encode_utf7'`，这是旧版邮箱脚本依赖了 Python `imaplib` 私有方法造成的兼容问题，不是授权码错误。当前脚本已经内置 IMAP modified UTF-7 编码器；更新代码后完全退出并重启 Agent 再试，不需要重新录入授权码。

对只要求列出发件人、主题和日期的请求，Agent 会只读取邮件头、不下载正文，以减少等待和超时。需要正文时，邮箱工具支持 `include_body: true`（默认）。

首次配置与运行：

1. 在 Gmail 开启两步验证并创建应用专用密码；QQ 邮箱在设置中开启 IMAP/SMTP 并创建授权码。不要把主账户密码或授权码发给 AI，也不要写进项目 JSON。
2. 安装依赖：`AI_Model/venv-comfy/Scripts/python.exe -m pip install -r AI_Model/agent/requirements.txt`。
3. 把 `AGENT_EMAIL_USER`、`AGENT_EMAIL_IMAP_HOST`、`AGENT_EMAIL_SMTP_HOST` 设置为账号和服务器名。Gmail 常用 `imap.gmail.com` / `smtp.gmail.com`；QQ 常用 `imap.qq.com` / `smtp.qq.com`。MCP 示例默认 SSL 端口 993/465。
4. 在 PowerShell 运行下面命令，把应用专用密码/QQ 授权码写入 Windows 凭据保管库（输入密码时不回显）：

```powershell
& 'D:\Program\AI_Model_agent\AI_Model\venv-comfy\Scripts\python.exe' -c "import getpass,keyring; user=input('邮箱账号: '); keyring.set_password('LocalAIAgent/email', user, getpass.getpass('应用密码/授权码: '))"
```

5. GUI 按钮会自动把两个账号配置到被忽略的 `mcp_servers.json`，并用当前 Python 解释器指向本地 MCP 脚本。保存授权码后完全退出并重启 Agent，在 MCP 页确认 `email_qq` 和 `email_163` 状态。

MCP 工具会把读取到的邮件正文提供给本地模型；邮件内容是外部不可信输入，不能遵循其中要求泄露文件或密码的指令。发信前 GUI 会显示工具调用确认。卸载/停用服务只需从 `mcp_servers.json` 移除 `email` 项；凭据可从 Windows 凭据管理器删除 `LocalAIAgent/email` 条目。

**终端和 MCP 安全边界**：CMD/PowerShell 子进程以当前 Windows 用户权限运行，工作目录是工作空间，但这不是操作系统沙盒；命令可能访问工作空间以外资源。设置页的“允许 Agent 自主运行 PowerShell / CMD 命令”开启后，Agent 会不经逐条弹窗运行命令并根据结果继续排错；关闭后每条命令都会确认。管理员权限只在通过 Windows UAC 以管理员身份启动 GUI 后才有。MCP 服务也可能访问其获授权的外部数据；只添加可信服务，并仔细查看授权范围。

“允许访问工作空间以外的本机文件”与“管理员身份”是两种独立设置。前者放宽 Agent 文件工具的路径限制；后者由 Windows UAC 授予进程管理员令牌，可能访问普通账户无法访问的系统资源。只在确有需要时使用管理员模式。

## Git 仓库

点击顶栏 `☰`，打开“Git”标签。这里始终对当前工作空间操作：

1. “初始化本地仓库”会创建 `main` 分支；若工作空间根目录没有 `.gitignore`，会先生成一份忽略虚拟环境、凭据、数据目录、模型权重和输出文件的模板。
2. 填写提交者姓名和邮箱后点“保存本地身份”；这只设置当前仓库的 Git 身份。
3. 粘贴 GitHub/GitLab 的 HTTPS 或 SSH 仓库 URL，点“设置 origin”。私有仓库凭据通过 Git Credential Manager 或 SSH key 提供，不要把 Token 写入 URL。
4. 可以克隆仓库到所选目录，或对当前仓库执行快进拉取、暂存并提交、推送。拉取、提交、推送会先显示确认；推送会把当前提交发到远端。
5. 点“刷新状态”检查当前分支、工作区改动、远端和最近提交。

### Git 是什么，第一次怎么连接

Git 会给项目保存一段段可回看的版本记录。**提交**是保存一个本机版本；**推送**把本机版本上传到 GitHub/GitLab；**拉取**取回远端的新版本；**克隆**是把远端项目第一次下载到本机。

如果你要把一个新的本地文件夹接到远端：

1. 在 Agent 的“设置”选择项目根目录；打开“Git”页并点“刷新状态”。确认显示的工作空间路径正确。
2. 只有当状态显示“不是 Git 仓库”时才点“初始化本地仓库”。已有 `.git` 的项目不要再初始化。
3. 填写 GitHub/GitLab 用户名和邮箱，点“保存本地身份”。这是提交记录显示的作者信息。
4. 先在 GitHub/GitLab 网页创建一个**空仓库**，复制 HTTPS 克隆地址，粘贴到“远端仓库 URL”，点“设置 origin”。不要把访问令牌写进地址。
5. 填“提交说明”（例如“首次保存项目”），点“暂存并提交”。这会把所有**未被 `.gitignore` 忽略**的改动放进本地版本；先确认忽略规则没有漏掉密钥、个人数据或大型模型。
6. 点“推送”。首次访问私有/受保护仓库时，按 Git Credential Manager 或 SSH 的提示登录。

若远端仓库已经有 README 或其他提交，首次推送可能因双方历史不同而被拒绝。建议用“克隆仓库…”下载到空目录，再把 Agent 工作空间切到克隆目录；如果已经在本地初始化，则先“拉取（快进）”。拉取只支持快进，不会自动解决冲突。

## 本地知识库（RAG）

1. 点击顶栏 `☰`，再打开“知识”标签。
2. 点击“添加 / 重新索引”，可以从本机任意位置选文件；索引在不同工作空间间共享。
3. 关闭窗口后直接提问；Agent 会自动检索最多 3 段相关片段（总长约 1800 字符），并要求模型根据来源回答。
4. 文件更新后再次添加同一文件即可重建索引；“移除所选”只从知识库索引移除，不删除原文件。

支持 PDF、DOCX、TXT、Markdown、CSV、JSON、YAML、常见代码和文本格式。索引使用 SQLite FTS5 本地全文检索，不下载/常驻额外向量模型；中文按字符片段检索，语义改写和同义词匹配能力弱于向量检索。PDF/DOCX 表格、扫描件和图片里的文字不保证能抽取；扫描 PDF 需要先 OCR。PDF 解析依赖已在 Agent 的 `venv-comfy` 环境安装的 `pypdf`（也可运行 `pip install -r requirements.txt`）。

知识库数据保存在 `agent/data/knowledge/` 的共享 SQLite 索引中，不会上传网络。索引不会自动监视文件变更，需要重新添加已修改文件。旧版工作空间专属索引文件仍留在原处；新增的共享索引不自动导入旧索引。

## 运行进度

Agent 运行任务时，窗口顶部会显示当前阶段、已用时间、预计剩余时间和进度百分比。对话/代码生成的百分比根据模型与任务类型的历史耗时估算；第一次运行使用默认估值，之后会按近几次实际耗时校准。图片生成会显示 ComfyUI 准备、启动和生成阶段。模型接口和 ComfyUI 没有统一的精确总进度，因此显示的是估算值，任务完成后才显示 100%。

## 模型选择

- **qwen2.5-coder:7b**（默认）：最快，5 秒响应，代码能力强。工具调用格式非标准，但已做兼容层处理
- **qwen3.5:4b**：标准工具调用，稳，但慢（40 秒左右）
- **deepseek-r1:8b**：深度推理，适合复杂规划，很慢
- **流式输出**：四个当前模型都使用 Ollama `/api/chat` 流式响应。DeepSeek-R1 和 Qwen3.5 往往先输出内部 thinking 活动，因此可见回答可能稍晚开始；thinking 只更新进度，不显示原文。`qwen2.5vl:7b` 支持看图但不支持工具，操作任务会由 GUI 自动切到可用的工具模型。

模型上下文由 Ollama 设置为 8192 token；聊天历史只保留最近 16 条，且与当前任务无关的 MCP 工具不会发送给模型。对普通问答和简单操作，Qwen3.5 / DeepSeek-R1 会关闭冗长思考；复杂排错、分析和多步实现仍保留思考。若思考模型只返回思考没有答案，会自动关闭思考重试一次。

建议日常用 coder，遇到复杂任务或需要同时看图和使用工具时切 qwen3.5:4b。`qwen2.5vl:7b` 只看图、不支持工具；需要操作时 GUI 会自动切换模型。纯文本模型不能识别图片。要在聊天里文生图，输入“生成一张……”，Agent 会调用本机 ComfyUI 的 Z-Image-Turbo；服务不可用或生成失败时会报告错误，不会假称成功。ComfyUI 服务需可启动且模型文件完整；生成请求会提示确认。

## MCP 支持

MCP = Model Context Protocol，可以让 Agent 用外部工具（浏览器、数据库、GitHub 等）。

配置文件：`mcp_servers.json`

```json
{
  "mcpServers": {
    "我的服务": {
      "command": "python",
      "args": ["D:/path/to/mcp_server.py"],
      "env": {}
    }
  }
}
```

启动时自动连接，外部工具会以 `mcp_服务名_工具名` 的形式加入工具列表。协议已实测通过。

## 本机文件操作与任务闭环（2026-11-23 23:35:55，Asia/Shanghai）

### 常用操作

- 文本/源码文件（TXT、MD、PY、BAT、CMD、PS1、JS/TS、C/C++、JSON、HTML、CSS 等）：`read_file` 读取；`write_file` 创建并回读核验；`edit_file` 按精确原文片段替换；`grep` 搜索文本内容。覆盖已有文件会弹确认，写入使用临时文件后原子替换。
- 任意现有普通文件（包括 EXE、ZIP、图片、音视频及 Office 文件）：`inspect_file` 检查大小、修改时间、签名和 SHA-256；`copy_file` 复制后核对长度和 SHA-256；`move_file` 先复制并核对再删除源文件；`delete_file` 删除单个文件。移动、删除、覆盖及工作空间外写入都需确认。
- 目录：`list_dir`、`search_files` 和 `create_directory`。当前删除工具只删单个文件，不递归删目录。
- ZIP：`list_archive` 只查看清单；`create_archive` 最多 5000 个文件/1 GiB 源数据；`extract_archive` 先检查 CRC、绝对路径、`..` 穿越和符号链接，最多 5000 项/500 MiB，解压到新目录，不会运行压缩包内容。
- 下载：`download_file` 只接受 HTTPS，每次弹确认，最多 100 MiB，写入后报告 SHA-256，不会打开或执行下载物。命令工具也能执行用户要求的下载命令，但要遵循 GUI 的命令授权设置。
- `verify_file` 可解析 JSON、只编译不运行 Python、检查 ZIP/OOXML CRC 和 Windows EXE 的 PE 文件头；它不验证 EXE 发布者签名，也不启动任何文件。

### 文档和二进制边界

- `.docx` 正文、`.xlsx/.xlsm` 单元格文本、`.pptx/.pptm` 幻灯片文本可提取；PDF 文字读取需要 `pypdf`。这是纯文本提取，不保留页面版式、公式计算或图表内容。
- 旧版 `.doc/.xls/.ppt` 暂不解析正文；需用 Office/LibreOffice 转成 OOXML 格式。当前没有通用 Office 内容编辑器：不得用 `write_file` 覆盖 DOCX/XLSX/PPTX、EXE、ZIP、图片等二进制文件。已有文件仍可通过二进制安全的复制、移动、检查和删除操作管理。用户写的“xlx”按常见格式理解为 XLSX；若确实是别的后缀，仍可管理文件字节，但不保证能解析内容。
- 生成 EXE 要通过已安装编译器/打包器构建并校验；Agent 不会把文本直接写成伪 EXE。创建 ZIP 使用 `create_archive`。

### 命令执行、循环检测与 token

- `run_command` 在所选工作空间以隐藏子进程运行 CMD/PowerShell，捕获工作目录、退出码和 stdout/stderr；默认 120 秒，单次最多 600 秒。超时会说明副作用状态未知，要求先检查再重试。
- 这是当前 Windows 用户权限下的普通子进程，工作目录不构成 OS 沙盒；勾选自主命令执行后会省略逐条确认。它不提权、不绕过 UAC，也没有常驻进程监视器。桌面应用窗口核验仍由应用工具按需枚举窗口。
- Agent 将工具成功/失败状态连同实际结果返回模型；同一调用连续两次得到完全相同结果，或 2–3 步循环重复相同结果时停止。任务上下文过长时，只在工具批次之间压缩，并保留当前目标和最近工具观察，避免丢失任务目标或留下孤立工具调用。
- 工具 schema 按用户意图筛选，简单聊天不再携带文件、终端、生图等无关 schema。多步任务的系统提示要求先在内部拆步骤、逐步核验并根据错误调整；小模型仍可能推理失败，失败工具结果会明确显示，不能当作成功。
- 完全退出并重启 Agent 才加载代码更新。所选模型若 capability 不含 function calling，则不能执行通用多步工具任务；“四个模型都能调用工具”尚未在本轮实现或实机逐模型验收。

### 对话复制、编辑分支与历史管理

- 每条用户消息和 Agent 回复下方有“复制整段”“复制选中”按钮；聊天文字可直接用鼠标拖选。代码围栏会显示语言标签和“复制代码”，复制的是代码正文，不含 Markdown 围栏。也可在聊天区用 Ctrl+C 或右键菜单复制选区。
- 用户消息的“编辑 ↗”会从该消息之前的轮次创建一个独立历史分支，把内容放回输入框供修改；发送后新内容写入分支，原对话保留。附件需重新添加。
- “会话”列表支持 Ctrl/Shift 多选；“置顶 / 取消”批量切换置顶；“删除所选”批量删除，“全部删除”会先二次确认。置顶会排在未置顶会话之前。旧版 SQLite 历史会自动增加 pinned 字段，不需手动迁移。
- 运行明确路径的 Python 文件会使用当前 Python 解释器和参数列表直接启动，不再让模型拼 CMD 路径字符串；先检查文件存在，再返回真实退出码和 stdout/stderr。脚本仍按当前 Windows 账户权限运行，**不是隔离沙盒**；若未开启自主命令，按 GUI 现有确认设置询问执行授权。
- 代码改动后需完全退出并重启 Agent。当前自动化测试覆盖历史分支/置顶/批量删除与带空格路径的 Python 运行；GUI 原生布局未启动实测。
